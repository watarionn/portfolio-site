# Prompt Studio 2.0 completion specification (2026-11-05)

## Authoritative decision
The new 2.0 application is **independent** of Prompt Studio 1.2 and PromptDB.
Legacy PromptDB reuse, import/export and schema compatibility are no longer required.
Do **not** delete or replace the old application until the new application is accepted on production/iPhone.
This document supersedes the compatibility/migration requirements in TEMPLATE_V2_DESIGN.md for the new completion goal.

## Screen A: Main
- Attribute selector (登場人物 / 場所 / ポーズ / 動き / アングル / 光 / 年代 / 画風, extensible in the dictionary).
- Value selector changes with the selected attribute.
- Multiple, independently selectable optional dropdowns depend on **the selected value**, e.g. woman has hair/body/hair color, dog has breed/fur/coat.
- [反映] fills the first matching literal placeholder \`{属性名}\` in the editor; if none is present, it appends the selected value and any optional details to the end.
- [選択をクリア] unselects the value and optional choices without erasing the prompt.
- Main prompt text is directly editable. [クリア] clears only the draft, [コピー] copies and stores one recent history entry, [保存] opens the two save options.
- Save as **template** stores a name and replaces specifically tracked inserted parts with \`{属性名}\`. Manually typed text is not guessed or silently replaced.
- Save as **prompt** stores the current resolved text and a name.
- [テンプレート] opens saved named templates and replaces the current draft after confirmation.
- [履歴] opens the last five clipboard copies plus all named saved prompts; choice replaces the current draft after confirmation.
- Repeated \`{登場人物}\` placeholders can be resolved independently, one at a time.

## Screen B: Dictionaries
Tabs: パーツ / テンプレート / プロンプト.
- Parts are hierarchical **attribute -> value -> optional dropdown -> choices**.
- Each level has add, rename and delete. Changes are reflected in Screen A.
- Templates and saved prompts are separately addable, editable and deletable.
- Deletion requires confirmation. Removing or renaming a dictionary attribute does not rewrite previously saved template prose. Current draft markers follow an attribute rename by stable ID; already saved template prose is not silently rewritten and must be edited separately.

## Storage and safety
- New localStorage key: \`prompt-studio-2.0-dictionary-v1\`; never read or write old PromptDB.
- New backup container: \`{format:"prompt-studio-2.0-backup",version:1,data:{...}}\`. Backup contains dictionary, templates, saved prompts, five-copy history, active draft and tracked markers.
- Import only this format, validate it and request confirmation before replacing saved work.
- Copy history is capped at five; saved prompts are not capped.
- JSON export is the portable backup. Browser storage is a working copy, not a long-term canonical repository.
- LocalStorage errors preserve the previous committed state. Unsaved text remains visible. Corrupt persisted JSON is protected, and backup export of an empty fallback is refused.
- Live text edits adjust unaffected marker ranges; editing inside an inserted part removes just that part's marker to prevent incorrect template substitutions.
- Text is rendered as textContent/text nodes; no generated content is injected as HTML.

## Layout and current shipping boundary
New standalone preview: \`tools/prompt-studio/v2-next.html\`, with \`v2-next.js\`, \`v2-next-core.js\`, \`v2-next.css\`.
New production path when scoped-deployed: \`/prompt-studio/v2-next.html\`.
Old \`/prompt-studio/\`, manifest, service-worker, PromptDB storage and legacy beta files are left untouched.
Official PWA switchover, new manifest/service worker, retirement of v1.2 and iPhone Safari acceptance are deliberately post-preview steps.

## Output format selector (2026-11-05 extension)
- Main editor has two explicit output modes: \`prose\` ("文章形式 / FLUX・GPT Image") and \`tags\` ("タグ形式 / SD1.5など").
- Mode changes **do not rewrite the current draft**. This prevents loss of free prose, hand-edited text, or saved part markers. The mode controls how **subsequent part reflections** are formatted.
- Prose mode retains the established Japanese rendering: \`女性（髪の長さ：ロング）\` and Japanese punctuation between appended parts.
- Tags mode appends comma-separated names/options without verbose Japanese attribute labels: \`女性, ロング, 電車\`; replacement of \`{属性名}\` remains deterministic and records marker boundaries.
- No automatic translation of Japanese parts to English, no semantic inference and no false claim of SD1.5 model-specific tag compatibility. The mode controls structure only.
- Browser persisted state and exported backups gain \`outputFormat\` (\`prose\` / \`tags\`). Existing standalone Prompt Studio 2.0 state and backup without this field are normalized to \`prose\`, without modifying their text.
- Copy history and named templates/prompts store their mode. Selecting a previously saved entry restores its draft and mode in one validated storage transaction.
- The v1.2 app and PromptDB remain untouched. The separate Beta Phase 3 is not overwritten.

## Japanese selection / English output (2026-11-05 extension)
- Dictionary attribute, value, per-value option and option-choice names remain in Japanese for selection and editing.
- Every dictionary item can have an explicit English expression (\`en\`). Values and choices may additionally have a tag-specific English expression (\`tag\`), defaulting to \`en\`.
- English category variable keys use lower-case ASCII with digits/underscores (e.g. \`character\`, \`location\`); templates displayed in Japanese lists use English placeholders in the actual prompt (\`{character}\`, \`{location}\`).
- Prose reflection uses English expressions, e.g. \`a woman with long hair\`. Tags mode uses tag expressions, e.g. \`1girl, long hair\`.
- Built-in dictionary items and built-in template bodies have explicit verified English equivalents. The two built-in template names and descriptions stay Japanese in the selection UI.
- User-created dictionary entries require both a Japanese display name and a manually supplied English expression in the dictionary editor. Do not use unverified runtime translation or fallback to Japanese in generated output. Missing English expressions cause an actionable error rather than inserting Japanese text.
- Template and named prompt editors distinguish Japanese selection name/optional Japanese preview from English prompt content. Japanese text is rejected as English prompt content for newly saved records.
- Older standalone 2.0 dictionaries are normalized non-destructively on load: built-in values receive English only when their stable ID and Japanese name match the original; *only* exact unedited built-in Japanese templates are upgraded to their English equivalents. User-created text, template prose and active drafts are **never** guessed/transformed; Japanese legacy content stays intact and can be edited explicitly in the dictionary before reusing. No old PromptDB import.
- Previously tracked part references use current category ID / English key when a new template is saved. Old draft and saved records are still available in 2.0 JSON backup, and invalid or missing custom translations do not destroy data.
- Manual text entered by the user is not an automatic translation request. Existing Japanese text triggers an actionable warning on part reflection/copy/new save, rather than silently changing or mistranslating it.
- All old v1.2 and legacy PromptDB assets are untouched; this applies only to the independent \`v2-next\` preview.

## Pending-edit safety fix
The Phase 3 editor now autosaves plain text as the user types when no variable references exist. If variable references exist, unconfirmed textarea changes are not silently flattened or exported as stale data. Save, copy and export instead display a confirmation-required warning until the user explicitly commits the text.

## Additional review: pending-text preservation
Found and fixed a concrete data-loss path: when a variable choice was changed while the textarea held uncommitted text, the guard previously called `render()`, overwriting the user's pending edits. It now restores only the select control's previous choice without rerendering the textarea.

The Python browser E2E test now explicitly checks that the pending textarea remains unchanged and the selected variable choice is reverted. The Python dialog input was also normalized to use a newline escape for two candidate options.

The updated browser E2E test has **not** been run against a real browser in this session. This is a code-review fix with a committed regression test, not a browser PASS.

# Webサイトの日本語表記・文章規則

適用範囲: 公開ポートフォリオのトップ、プロフィール、作品紹介、ウェブアプリの画面文言。
2026-10-22のユーザー指示に基づく。既存の機能、公開URL、識別子、仕様、画面固有の事実を保持する。

## 1. 表示言語

- 日本語で自然に表せるナビゲーション、見出し、ボタン、状態、補助ラベル、説明文は日本語に統一する。
- 作品索引に表示する作品名は日本語にする。正式な製品名、ファイル名、GitHubリポジトリ名、URL、`data-*`、API名、プログラミング言語名は不用意に改名しない。
- 英語は固有名詞、正確な技術用語、コード、引用、外部仕様との照合に必要な場合のみ残す。
- 多言語対応が必要な製品は、日本語ユーザー向けの標準UIを日本語とし、翻訳と内部キーを分離する。

## 2. 日本語の句読点

- 読点「、」は主語や修飾語の係り先、列挙、読み違いの防止、長い文の意味の区切りなど、国語として必要な箇所に使う。
- 広告的な間や見栄えを作るためだけに、短い主語・述語、目的語・述語、連体修飾語・名詞などを読点で分断しない。
- 特に「○○を、○○に。」「○○は、○○。」「○○だけでなく、○○へ。」を短い見出しの定型文として使わない。
- ただし読点が意味上・文法上必要な文章まで機械的に削除しない。文脈と実際の可読性を人が判定する。
- 見出しは情報を直接表す名詞句または自然な文章にする。意味のない句点、三点リーダー、感嘆符は使わない。
- 体言止め、倒置、リズム優先の断片文、過度に抽象的な宣伝表現を常套句にしない。

## 3. キャッチコピー・Hero表現

- 広告的なキャッチコピー、誇張、単独の`hero-lead`、大きな宣伝文を追加しない。既存の同類表現は削除または事実ベースの説明へ書き直す。
- `hero`などのCSSクラス名があるだけでは削除理由とせず、その領域の情報上の役割を判断する。既存の検索UIや操作ボタン、識別に必要なページ名は維持する。
- 製品の操作に必要な説明はヘルプ、フォーム付近、仕様節など、本来あるべき位置へ置く。作品固有の世界観や設定の本文は宣伝文と混同しない。
- 「便利で革新的」「無限の可能性」「○○を、もっと自由に」といった抽象的な広告調を避け、機能、制約、対象、結果を具体的に説明する。

## 4. 既存サイトのデザイン判断

- トップは大きなHEROや人物紹介を置かない、作品中心の「個人大辞典」を維持する。
- 注目作品は指定されたポーズスタジオ、参照図形エディター、画像簡略化ツールとする。
- 実画面の撮影画像がない作品に、別の作品のスクリーンショット、架空のUI画像を流用しない。
- 文字の縮小で判読性やタッチ操作を犠牲にしない。iPhoneとデスクトップを別々に検証する。
- この規則を理由に、作品ごとの独立したデザイン、仕様、ゲーム内の文章、著作物の引用、翻訳原文を一括書換えしない。

## 5. 新規ページ・改修の確認

1. 画面に表示される日本語化可能な英語を確認する。
2. Heroやcatchcopy、不要な長いリード文がないか確認する。
3. 文節の読点が文法・可読性のために必要か、一文ずつ確認する。
4. 作品名・リンク先・技術名・内部IDが一致するか確認する。
5. 320px級の狭い画面、標準のデスクトップ、タッチ・キーボードの導線を確認する。
6. 機能説明、必要な警告、エラー修正手順など、利用者に必要な情報を誤って削除していないか確認する。

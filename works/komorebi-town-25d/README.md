# こもれび町 2.5D（視覚強化試作）

このページは `/komorebi-town-25d/` の独立した試作品。旧 `/komorebi-town/`（3D）と、ポートフォリオサイト本体は変更しない。

## 追加した表現
- 4つの施設に個別装飾（図書館、工房、展示館、あそび場）。屋根瓦、柱、窓、看板、植木鉢など
- 広場の噴水、水紋、街灯、花壇、ベンチ
- 昼・夕方・夜の切り替え、窓の灯り、蛍、舞う花びら、工房の煙
- 住民の軽い移動、歩行の上下動
- 描画更新を約30fpsに抑え、reduce-motion時には演出を止める

## 実装境界
- `public/index.html` : UI、固定アイソメトリックカメラ、移動・経路探索、会話、入力
- `public/art-layer.js` : 純粋なCanvas 2D上の装飾と光演出。ネットワーク/追加ライブラリ不要。読み込み失敗時は既存ゲームとして動作
- 本実装は絵柄・端末性能・入力の受け入れを判断する試作段階。PixiJS/Tiled/Pixeloramaをすぐ導入しないのは、見た目の評価より先にランタイム全体を入れ替えないため
- 書き換え対象はこの独立プレビュー2ファイルのみ。本番トップ、既存3D、Portfolio Cityは変更しない

## 動作確認
- Node `--check`：HTML内スクリプト、art-layer.js
- Chromium 1280x800：初期化、昼→夕方→夜、描画エラーなし
- Chromiumモバイル幅393x852：タップ入力、方向パッド表示、横スクロールなし、描画エラーなし
- iPhone実機操作は公開後の受入項目。WebKitで実測していない状態では「iPhone検証完了」としない

## 公開
GitHub `main` 統合後、`scripts/release_komorebi_25d_visual.py` によるWinCredのFTPS限定更新。現行データのSHA-256を確認し、`art-layer.js`→`index.html` の順に配信して、両ファイルのFTPS/HTTPSのハッシュ読戻しを行う。HTML更新失敗時には旧HTMLへ戻す。

## 2026-11-15 iPhone向けの描画負荷対策
- ユーザーのiPhone受入で「少し動作が重い」との報告。実機のプロファイラは未取得なので、以下の原因はコード上の負荷候補として扱う。
- 27×27タイルの地面を起動時と画面サイズ変更時だけ透明Canvasに生成し、毎フレームのタイル描画をキャッシュ画像の転送へ置き換えた。メモリ不足時には従来描画にフォールバックする。
- 画面外の木・建物の描画を省略し、木・建物の静的描画順情報を再利用。タップ経路探索用の歩行可能セルを起動時に計算する。
- 昼の光、周辺減光、街灯、窓の光のCanvasGradientを再利用。画面サイズや時間帯が変われば必要なものだけ作り直す。
- タッチ端末で描画時間が平均24msを超えた場合に20fpsへ調整し、13ms未満に回復すれば約30fpsへ戻す。背景タブでは描画を休止する。
- Safariの古いJSキャッシュを避けるため、HTMLは `art-layer.js?v=20261115-perf` を参照する。

### 回帰テスト
```sh
node works/komorebi-town-25d/tests/art_layer.test.mjs
node works/komorebi-town-25d/tests/performance.test.mjs
```

- Chromium（393×852、タッチ有効・CPU 4倍減速）の同一条件における1描画の平均は、最適化前約7.4ms、最適化後約4.4ms（参考値。実測条件によって変動する）。
- 開発ブラウザで昼夕夜の切替、タップで移動、画面幅、JavaScriptエラー0を確認。
- この数字はiPhone実機のFPS・動作保証ではない。公開後に改めてiPhoneで操作感を受け入れ確認する。
